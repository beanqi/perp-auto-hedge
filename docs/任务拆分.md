# 任务拆分

本项目按主链路拆分为 6 个阶段，优先把核心流程跑通，再补充细节。

原则：

```text
Simple > Clever
Small Diff > Architecture Rewrite
先跑通主链路，再增加能力
```

---

## 1. 整体框架搭建

- 建立项目目录结构
- 配置基础依赖、日志和配置读取
- 搭建主程序启动流程
- 建立 Engine 主事件循环
- 建立 Exchange / Market / Strategy / Risk / Execution / Storage / API 基础模块

完成标准：

```text
程序可以正常启动
→ 各模块完成初始化
→ Engine 可以运行并处理基础事件
```

---

## 2. 核心结构体定义

定义模块之间需要传递的核心数据：

- `MarketId`
- `Instrument`
- `PriceLevel / OrderBook`
- `Balance / Position`
- `Order / Fill`
- `Pair / PairRuntime`
- `ActiveTrade`
- `OpenPlan / ClosePlan`
- `MarketEvent / AccountEvent / ExecutionEvent`
- `SystemState / PairState`

重点先把数据边界定义清楚，不提前增加复杂抽象。

完成标准：

```text
Exchange
→ Engine
→ Strategy / Risk
→ Execution
```

之间的数据可以使用统一结构完整表达。

---

## 3. 交易所接入

先完整接入一个交易所，再增加其他交易所。

Spot / Perp 分开实现。

### 行情

- 获取 Instrument Catalog
- 接入 Spot L1 实时深度
- 接入 Perp L1 实时深度
- 转换为统一多档 `OrderBook`
- 接入 Funding

### 账户

- Balance
- Position
- Borrow / Margin 信息
- OpenOrder 查询

### 交易

- Private WebSocket 订单状态
- Fill 推送
- Trading WebSocket 下单
- Trading WebSocket 撤单
- WebSocket 重连
- 基础 Reconcile

建议实现顺序：

```text
行情
→ 账户
→ 订单推送
→ 下单
→ 撤单
→ Reconcile
```

完成标准：

```text
实时行情
+ 账户状态
+ WebSocket 下单
+ Order / Fill 生命周期
```

可以完整跑通。

---

## 4. 核心引擎

### 4.1 数据流处理

- Exchange Event 进入 Engine
- 更新 `MarketStore`
- 找到受影响的 Pair
- 驱动对应 PairRuntime
- 根据 PairState 处理当前事件

### 4.2 策略与机会计算

- OrderBook 多档撮合
- VWAP
- Spread / Residual / Z 等核心指标
- Entry 判断
- Exit 判断
- 基础 Risk Gate

### 4.3 订单执行

- 生成 `OpenPlan / ClosePlan`
- 双腿下单
- Ack / Order Update / Fill 聚合
- 超时处理
- 撤单
- 部分成交处理
- 两腿数量差异处理

### 4.4 状态维护

维护 Pair 主状态：

```text
WARMING_UP
→ WATCHING
→ OPENING
→ HOLDING
→ CLOSING
→ WATCHING
```

异常统一进入：

```text
RECOVERING
或
HALTED
```

所有 PairState 只由 Engine 修改。

### 4.5 结算

- 记录实际开仓成交价
- 记录实际平仓成交价
- 统计 Fee
- 统计 Funding
- 统计 Borrow Cost
- 计算最终 PnL
- 保存 Completed Trade
- 释放 Risk Exposure

### 4.6 异常恢复

处理：

- 单腿成交
- 两腿数量不一致
- Trading WebSocket 断线
- 订单状态无法确认
- 本地状态与交易所仓位不一致
- 程序 Restart Reconcile

完成标准：

```text
行情
→ 发现机会
→ 开仓
→ 成交
→ 持仓
→ 平仓
→ 结算
```

完整套利生命周期可以跑通。

---

## 5. 前后端通信

后端提供简单 HTTP API + WebSocket 推送。

### 查询

- SystemState
- Exchange 连接状态
- Pair 列表和状态
- 实时指标
- 当前 Position
- Active Trade
- Order / Fill
- Completed Trade

### 实时推送

- Pair 状态变化
- 行情 / 核心指标变化
- Position 变化
- Order / Fill
- Trade 状态变化
- 系统异常

### 控制

只提供必要操作：

- Start
- Stop
- Halt
- 必要的人工 Recovery 操作

完成标准：前端不读取后端日志，也可以获取系统所有关键运行状态。

---

## 6. 前端展示

第一版只做运行监控，不做复杂交易终端。

页面保持简单：

```text
Dashboard
Pairs
Positions
Orders / Trades
System
```

主要展示：

- 系统运行状态
- Exchange / WebSocket 连接状态
- Pair 状态
- Spread / Z / EV 等核心指标
- 当前仓位
- 未完成订单
- 成交记录
- PnL
- RECOVERING / HALTED 异常
- 基础启动 / 停止控制

完成标准：不查看后台日志，也能知道系统当前在做什么、有什么仓位、是否存在异常。

```text
M1：实时行情跑通
M2：完整订单生命周期跑通

```
